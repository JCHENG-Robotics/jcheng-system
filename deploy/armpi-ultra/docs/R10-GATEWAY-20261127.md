# R10 hardware gateway deployment — 2026-11-27

Status: **Partially verified**. The gateway was built and served live `/v1`
traffic on the robot on 2026-11-27, but no motion command was sent and the
hardware motion path remains unexercised.

This record covers `jcheng_gateway_vendor` (R10), the hardware-backed
`GatewayApp` HTTP surface that the operator console uses for
`/v1/health|contract|state|safety` and, when a lease exists,
`/v1/motion/validate|execute|stop`. It is not an e-stop, brake, encoder or
self-collision model.

## 1. Safety model

- The node refuses to start without `enable_motion:=true` and a token.
- It starts `DISARMED`; execution still needs an armed safety state and an
  operator-supplied lease.
- It binds `127.0.0.1:8766` on the host network. The console reaches it through
  an SSH tunnel; do not widen the bind to reach it from the laptop.
- The unit is **manual start only**. It is never enabled at boot.
- The legacy `armpi-gateway-pose` unit also uses 8766 with `--enable-motion`.
  Mask/stop it before starting R10; the installer refuses to run while it is
  active.
- `jcheng-rrc-guard.timer` skips itself while `jcheng-gateway-vendor` is
  active. A CH340 re-enumeration during a motion session is still an operator
  stop/restart, not an automatic controller restart.

## 2. Build (inside the vendor container)

The container already carries ROS 2 Humble, CycloneDDS and
`ros_robot_controller_msgs`. Copy this checkout to the robot and build it as
`ubuntu`:

```bash
docker exec -u ubuntu ArmPiUltra /bin/bash -lc '
  set +u
  source /opt/ros/humble/setup.bash
  source /home/ubuntu/ros2_ws/install/setup.bash
  source /home/ubuntu/jcheng-m5/install/setup.bash   # jcheng_interfaces v0.1.0
  cd /home/ubuntu/jcheng-r10
  colcon build --base-paths ros2_ws/src \
    --packages-up-to jcheng_vendor jcheng_bringup
'
```

`JCHENG_INTERFACES_WS` points at the prefix that provides
`jcheng_interfaces` v0.1.0; the example above uses the existing M5 build.
Build the interfaces in the same workspace if a self-contained tree is
preferred, then leave `JCHENG_INTERFACES_WS` empty.

The vendor stack (`start_node.service`) must be running and
`/ros_robot_controller/bus_servo/get_state` must exist. The startup fix in
`gateway_node.py` performs the first bus read from a one-shot timer after the
executor is spinning; a synchronous read in `__init__` deadlocks.

## 3. Install

```bash
cd deploy/armpi-ultra
sudo ./install-gateway-vendor.sh            # install only
sudo ./install-gateway-vendor.sh --start    # operator-authorized start
```

The installer writes `/etc/jcheng-system/vendor.env` (0600), installs
`/usr/local/lib/jcheng-system/jcheng-gateway-vendor-run.sh` and
`jcheng-gateway-vendor.service`, and does **not** enable the unit at boot.
Paths can be overridden with `JCHENG_WS`, `JCHENG_ROOT`, `JCHENG_VENDOR_WS`,
`JCHENG_INTERFACES_WS`, `JCHENG_VENDOR_PORT` and `JCHENG_EVIDENCE`.

## 4. Verify

From the robot host:

```bash
curl -s http://127.0.0.1:8766/v1/health
TOKEN="$(sed -n 's/^JCHENG_GATEWAY_TOKEN=//p' /etc/jcheng-system/vendor.env)"
curl -s -H "Authorization: Bearer ${TOKEN}" http://127.0.0.1:8766/v1/contract
curl -s -H "Authorization: Bearer ${TOKEN}" http://127.0.0.1:8766/v1/state
curl -s -H "Authorization: Bearer ${TOKEN}" http://127.0.0.1:8766/v1/safety
```

Expected: `status=ok`, contract `0b8d72…`, five measured joints,
`state=DISARMED`, `stop_latched=false`. Evidence from the live deployment is
in `../evidence/20261127-r10/`.

## 5. Studio wiring

The console is an HTTP/WS client and never joins DDS:

```ini
ARMPI_GATEWAY_V1_URL=http://127.0.0.1:8766
ARMPI_GATEWAY_V1_TOKEN=<token from vendor.env>
ARMPI_SYSTEM_STOP=1
```

`127.0.0.1:8766` on the console host is an SSH forward to the robot's loopback
(the gateway is not LAN-reachable). The stop proxy requires a loopback URL with
an explicit port; `ARMPI_SYSTEM_STOP=1` is refused at startup without both V1
variables.

## 6. Port conflict and legacy pose gateway

`armpi-gateway-pose.service` (legacy, `--enable-motion`, LAN-bound 8766) must
be stopped and masked before R10 is started. On 2026-11-27 the original unit
was backed up to `/root/armpi-gateway-pose.service.bak-20261127` and replaced
with a `/dev/null` symlink. To restore it: remove the symlink, move the backup
back, `systemctl daemon-reload`.

## 7. Limits

- No motion command was sent in this record; `/v1/motion/execute` is
  unexercised on hardware.
- The bus-servo read has no safe timeout; a wedged DDS reader needs a restart
  of the owning process, not a retry loop.
- The unit is not enabled at boot; a robot reboot requires an operator start.
